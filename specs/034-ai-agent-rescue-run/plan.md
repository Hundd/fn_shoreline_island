## Three-beat layout and fun

Origin is (-12000,-15300,2400) cm. Dispatch/floor1 local X=68..102, Route Rescue/floor2 X=34..68, Delivery Check/floor3 X=0..34. Arrival strip X=94..102 is annotation only; no new walls. Proposed firing points: (76,18,0), (54,18,0), (30,18,0). Approach from (98,13,0) via (92,18,0) is about 24 m; following Pix adds 22 m then 24 m. Walking contributes a visible companion journey, not repeated backtracking. Return exists at each beat. Finish Replay teleports the owner back to Dispatch. No timer punishes slower players. Pix waits at the beat endpoint until the owner is within 6 m of that beat's firing point; processing arrival never skips earlier phases.

Each bank has three 1.5 m faces centered X=firingX-3, firingX, firingX+3; Y=10,Z=1.8, facing +Y. Targets are 8 m ahead; labels stay below rings with redundant words/icons. Each main board face center is (firingX,2,4.8), maximum 8 x 2 m. Its native pivot must be measured; target and board readability cannot be inferred from font values. Scene props remain below the board line. Use the existing stationary target APIs and park inactive hit surfaces so they cannot intercept shots. No labels announce correctness in advance.

Pix is a reusable creative_prop assembly (body with face components), never an AI navigation pawn. Scripted center path is [(76,6,0.6),(54,6,0.6),(54,3,0.6),(30,3,0.6),(30,6,0.6)]. The Medical crate follows with a fixed visible carrying offset until the lab drop at (30,6,0.5); reset to exact saved homes. At the first segment's end, a striped safety gate at (50,6,1) changes from OPEN to CLOSED and Pix pauses at (54,6,0.6), 4 m short. Gate movement only affects the robot display lane. Scan reveals Dock; selecting it resumes the same delivery along the 3 m-offset detour, then Drop. Three project-primitive crates carry clear FOOD/MEDICAL/TOOLS labels. Reuse existing destination scanner and eligible Pix/crate/core materials; no external assets. Existing movable prop parts may form one role assembly; the 11 prop-role count is not a promise that there are only 11 mesh components.

This is a three-scene escort story with surprise, visible autonomous execution, a rescue intervention, and a physical result to inspect. Five decisions remain deliberately simple for ages 8–10. No reflex or combat layer is added to make it seem fun. Cooked first-time-player timing, understanding and enjoyment determine whether the presentation succeeds.

States: locked/idle -> choose cargo -> launch skill -> moving to closure -> wait for owner -> scan -> reroute -> moving to lab -> wait for owner -> verify -> celebrate/finished. Success IDs are [1,0,3,5,7]. Current beat bounds, current owner, active phase, input quiet period and generation must all match. Each segment checks MoveTo results and the actual final prop transforms. Canceling a generation must stop/settle outstanding moves before restoring saved transforms; merely ignoring late credit while an old animation can overwrite new homes is insufficient. A failed segment restores its segment-start pose/carrying state and returns to its launch decision. Final verification independently checks current generation, valid Medical identity, successful required action history, crate position within 0.5 m of the lab drop, Pix at lab, and crate no longer in carrying pose. Do not trust a delivery_complete bool alone. AC-11 deliberately invalidates the physical evidence to test this.

A player using floor4 cannot simultaneously own rescue; acquire/release station ownership through the existing per-player station_id convention with a distinct documented rescue identity.
