# Prompt Workshop implementation plan (draft)

## Decision and reuse

Replace the current five-shot Prompt Lab lesson with four compact activity areas: Inspect, Compose, Test/Revise, Connect. The current feature-026 approved layout remains the measured baseline until this feature is explicitly approved. User wording authorizes retiring old Prompt Lab game assets; this plan uses selective reconciliation so shared systems and unrelated stations survive.

The feature-023 `fn_shoreline_island_prompt_lab_controller` already has personal choice state, button subscriptions, a prompt readout, Send, visible wrong-core/wrong-destination Pix actions, replay, and an existing badge call. It is currently disabled by `use_blaster_mode=true`; the live feature-026 `fn_shoreline_island_prompt_blaster` is active. Reuse the legacy controller as the implementation basis, not as evidence that this proposed one-request mission already works. The new `prompt_workbench` pattern describes this bounded adapter. A scoped Verse refactor must replace its three-challenge/rail/cube flow with the spec's three-slot request, preserve generation cancellation, add per-run DATA awards, and ensure exactly one Prompt Lab controller subscribes/acts. Do not create a generic arbitrary-prompt engine.

## Geometry and player flow

Map coordinates are local meters from world `(6000,-8500,2410)` cm. The 66 x 62 m platform and entry `(15,33,1.9)` are historical measured evidence; proposed stations, controls and props are design anchors, not native transforms. The west ramp stays open. The normal path crosses `(15,40) -> (27,40) -> (43,40) -> (59,40)` with 3 m intended clearance. The module is currently at `(64,23,2.7)`, so the last Connect interaction requires a visible northward walk within the reward area; keep its button near the existing module and signpost the turn. The player should not need a rail, jump, or precision edge. Movement between Inspect and Compose is about 16 m; Compose to the reward area is about 16 m, followed by a roughly 18 m module approach. The inspection scene remains in view from the choice controls if visibility permits; cooked sightline proof is required.

The inspect scene has two blue sizes 7 m apart, both with readable text/shape cues. Choice groups are 5 m apart as group centers, with two buttons per group. The continuous prompt readout sits between the choices and Send; it must show current WHAT, WHICH ONE and WHERE, including blanks. The test result runs across the player's view toward the reactor and returns after a wrong request. The preview envelopes mark activity, not walls or automatic placement commands.

## Design decisions and limits

- The old rail and carryable cube are outside the required route. Retain or retire them only after actor ownership and other-mission use are checked. The optional feature-026 return rail remains outside acceptance; walking west is the required exit.
- DATA total stays 8 for one fresh successful run, but timing changes to 5 on accepted Send plus 3 on Connect. This is an intentional gameplay change requiring approval and implementation code.
- Feature-023 cooked/build evidence proves a controller and devices existed, not that the simplified flow, current bindings, collision, or two-player lifecycle work today.
- Map contract v1 cannot draw three independently editable slots, per-player UI, the Pix path, or collision. The generated implementation YAML is an intent list. The exact deletion/move delta is an implementation preflight deliverable, with any material change returned to design review.

Approval of this revision should use `generated/review-manifest.json` and `approval.yaml`, followed by `python tools/map_workflow.py plan specs/027-prompt-workshop-redesign/map.yaml --ready`. Then use `$uefn-map-implementation` for serialized editor work and verification. No approval is recorded yet.
