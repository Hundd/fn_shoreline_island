# Verse host representation and placement

Auxiliary Verse devices use a neutral Cube editor locator instead of the Agency computer. This is an explicit per-instance configuration process. UEFN's generated class default is unchanged; a newly dragged Verse device may still start with the Agency computer.

Feature 059 proved the existing-instance mechanism on prompt_blaster_target_0: its existing StaticMeshComponent0 mesh was changed through native ObjectTools, native construction automatically refreshed the material to WorldGridMaterial, and the same actor/script, transform and bindings survived save, native Verse compilation and an isolated external-package reload. See [pilot evidence](../specs/059-verse-host-representation/evidence/pilot-r2-result.md). A fresh placement and whole-editor restart were not tested by that pilot. Do not describe this as a verified automatic default or template.

## Configure each auxiliary host

1. Place the required compiled Verse class normally. Do not duplicate a live configured mission or target device as a factory: that can copy IDs, script settings and bindings. For existing hosts, retain the existing actor. Record GUID/path, script class/instance, full transform, intended purpose and relevant references before editing.
2. Confirm the actor is auxiliary logic. Target hit surfaces, target graphics, interactive controls and scenery are separate purposes; do not turn them into generic cubes. Preserve exact transforms because some controllers use their host location for spatial checks.
3. Discover the current native schemas and select the existing StaticMeshComponent0. UEFN Details exposes its Static Mesh field. Use the live-exposed ObjectTools.set_properties on the EXACT COMPONENT instance with this JSON values string:

   {"staticMesh":{"refPath":"/VerseEngineAssets/Cube.Cube"}}

   The actor-level staticMesh field was rejected in the first pilot. Leave actor.staticMesh at its native baseline (null in tested hosts). Never target a shared Blueprint/class default, replace the stateful actor or add a second component.
4. Require successful native result and immediate component readback as Cube. Inspect overrideMaterials and material parent: the proven pilot automatically produced a transient MID whose parent is /Engine/EngineMaterials/WorldGridMaterial.WorldGridMaterial. Transient MID names may vary; never hardcode the pilot MID path as a material asset. Do not clear or overwrite material overrides when native refresh already succeeded. If Agency material persists or appearance is wrong, stop and obtain a specifically reviewed reset/correction; generic trial-and-error changes are not this procedure.
5. For proven auxiliary/nonphysical hosts, set actor visibleInGame=false and bNoCollision=true through the discovered native fields. These are role-based representation settings, not permission to disable actual hit/control collision. Confirm expected script startup behavior and separate functional bindings first. Feature 059 applied this configuration to all 71 existing auxiliary hosts and verified it after native compilation and isolated reload of all 71 packages. Native component readback becomes hidden in game, with QueryOnly/Custom collision and ignored responses except Visibility overlap; this editor-query state does not prove cooked collision behavior. The original mesh-only pilot preserved its original flags.
6. Read back GUID/path, script class/instance, complete actor/component transforms, actor mesh override, component mesh/materials, visibility/collision flags, enabled state and intentional editable bindings. Confirm no live target IDs or references were copied accidentally. Assign only the new host's intended references.
7. Save only the affected actor/external package and confirm clean state. Build Verse natively, inspect diagnostics, reacquire actor/component by identity and repeat readback. For persistence verification use supported targeted reload of the exact clean saved external package, with checkpoint and unrelated dirty work protected; reacquire references afterward. If isolated reload is unavailable or fails, report persistence pending instead of treating in-memory readback as reopen proof.
8. Before handoff, run a whole-current-scene StaticMeshComponent census, including derived component types, matching Agency_Computer in actual mesh paths. Record descriptor count, successfully inspected count, all errors and remaining matches. A label-only search misses renamed hosts. Resolve auxiliary omissions through this process; classify unexpected functional/scenery instances separately. Do not claim zero computers when any descriptors could not be inspected.

## Recovery and evidence limits

Capture exact original mesh/material state and checkpoint before edits. Restore original values through the supported component field only while captured references remain valid. Generic component reset may use a class CDO rather than the placed component archetype and may not restore Agency; do not assume it is safe. Transient material refs can become invalid after reload. Use established supported recovery rather than guessing transient names or overwriting a loaded binary.

No shared Epic asset/default edits are required. A future-placement checklist prevents omissions operationally; it does not change the generated default. Each fresh placement needs its own verification because only an existing bound instance was tested in the pilot.

Native editor evidence does not establish cooked gameplay. For task 059, the owner reserved spawn, target/control interaction, progression, replay/Return, reset, solo/shared state and collision testing for manual acceptance; do not launch games, sessions, cook or push as part of this work.
